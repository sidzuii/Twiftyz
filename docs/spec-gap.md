# Сверка ТЗ ↔ текущий проект

Дата: 2026-06-30. Легенда: ✅ есть · 🟡 частично / заглушка · ❌ нет.

Текущая реализация — локальный modular monolith на стандартной библиотеке Node.js
(`server.js` + `public/*` + `data/store.json`). Это рабочий MVP, но не production-кластер из ТЗ.

## Покрытие по разделам ТЗ

| § | Раздел ТЗ | Статус | Что есть / чего не хватает |
|---|-----------|--------|----------------------------|
| 2 | Платформы | 🟡 | Есть Web-клиент. Нет Android/iOS/Desktop (Electron/Tauri). |
| 3 | Регистрация и авторизация | 🟡 | Есть регистрация email/телефон, вход по email/телефону/нику, пароли `scrypt`, bearer-сессии, список и отзыв сессий, смена пароля. **Полный двухфакторный auth-флоу:** регистрация в 2 шага (форма → код на email → аккаунт); вход = пароль + код подтверждения **всегда**. Код входа доставляется **сообщением в служебный чат «Twiftyz»**, если у пользователя есть активная сессия; иначе — **экран восстановления** (email+телефон+никнейм → код на почту). **Сброс пароля** по коду на email (с отзывом всех сессий). Доставка email zero-dependency (SMTP домена reg.ru/465 или Brevo), TTL/кулдаун/лимит попыток, `emailVerifiedAt`. Нет: TOTP/WebAuthn, SMS-доставки, STARTTLS-587. |
| 4 | Профиль | 🟡 | Базовые поля и аватар есть. Нет полноценных настроек приватности видимости (телефон/email/онлайн/контакты). |

| 6 | Личные чаты | 🟡 | Доставка, прочтение, typing, presence, реакции, ответы, закрепы, файлы, поиск, **редактирование/удаление в UI**, **превью ссылок** (OpenGraph, zero-dep), **инлайн-картинки вложений**, **голосовые сообщения** (MediaRecorder → webm, audio-плеер в бабле), **цитаты в ответах** (автор+текст, клик — переход к сообщению), **лайтбокс изображений**. ## Дизайн / UI (§4 этапов, «современный интерфейс»)

- ✅ Современный layout (rail + список + диалог + инспектор), карточки, bubbles, mobile-режим.
- ✅ **Тёмная тема + автоопределение системной** (`prefers-color-scheme`, переключение в реальном времени, без мигания при загрузке).
- ✅ Единая дизайн-система на CSS-переменных (один источник правды вместо двух конфликтующих скинов).
- 🟡 Иконки — Unicode-глифы (`⌕ ➜ ☎`). Для финального вида стоит заменить на SVG-набор.

## Рекомендуемый порядок движения к полноценному мессенджеру

Ближайшие шаги (без смены стека, наибольшая отдача):
1. Редактирование/удаление сообщений в UI, черновики, превью ссылок.
2. Реальный WebRTC signaling для звонков (audio → video → screen share).
3. Превью и прогресс загрузки файлов, изображения инлайн.
4. Настройки приватности видимости профиля (§4).

Переход к production-стеку из ТЗ (§21–23):
1. Вынести `data/store.json` → PostgreSQL + миграции.
2. Redis для сессий, presence, rate limiting, pub/sub между инстансами.
3. S3-совместимое хранилище с presigned upload/download вместо `uploads/`.
4. Очереди (BullMQ/RabbitMQ): push, превью, антивирус, транскод медиа.
5. Разбить `server.js` на модули NestJS (auth/users/chats/messages/media/calls/admin).
6. Web-клиент → Next.js + TypeScript + Zustand, переиспользовать API/WS-контракты на mobile/desktop.
7. TLS reverse proxy + security headers; TOTP/WebAuthn 2FA; верификация email/телефона; сброс пароля.
